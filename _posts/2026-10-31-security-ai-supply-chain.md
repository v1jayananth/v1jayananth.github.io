## Safe Serialization Formats

* **SafeTensors**: Eliminates arbitrary code execution vectors inherent to Python `pickle` by utilizing a strictly typed, memory-mapped format for tensor storage.
* **PyTorch `weights_only=True`**: Restricts the unpickler to tensor reconstruction and basic data structures, preventing arbitrary object instantiation. This serves as the default behavior in PyTorch 2.6 and later.

### Convering pickle to SafeTensors

```python
import torch
from safetensors.torch import save_file, load_file

# Step 1: Load the existing pickle model safely
# (weights_only=True restricts what pickle can do; explained in Defence 2 below)
model_weights = torch.load("model.pkl", weights_only=True)

# Step 2: Save as SafeTensors
save_file(model_weights, "model.safetensors")

# Step 3: Load the SafeTensors model (always safe)
safe_weights = load_file("model.safetensors")
```

## Model Verification and Integrity

* **Cryptographic Hashing**: Utilize `sha256sum` to verify artifact integrity against published checksums before deployment.
* **Model Cards**: Audit model documentation for training provenance, limitations, and intended deployment scope.
* **LoRA Adapter Risks**: Treat fine-tuning adapters as executable code; malicious code can be injected into adapter weight matrices independently of base models.
* **Staging Isolation**: Ingest all external model artifacts into an isolated staging network zone for validation before promoting to production.

---

## Behavioral Analysis

* **Audit Hooks**: Implement runtime monitoring via Python `sys.addaudithook()` to intercept high-risk system calls, network sockets, and file operations during model loading. Introduced in Python 3.8. 
* **Analysis Tools**: Deploy scanners such as **Fickling** and **ModelScan** to inspect serialized structures.
* **Detection Limitations**: Behavioral and static scanners rely on known attack signatures and heuristics, failing to guarantee complete coverage against novel or heavily obfuscated exploit mechanisms.

## Architecture-Level Threats

* **Lambda Layers**: Keras Lambda layers embed arbitrary Python code expressions within model architecture files, triggering execution upon model loading.
* **Architecture Inspection**: Utilize automated structural analyzers (e.g., ModelScan `H5LambdaDetectScan`) to inspect model topologies and flag embedded executable code structures.

## Dependency Auditing

* **Version Pinning & Lockfiles**: Enforce strict version constraints and dependency locking (e.g., Poetry, pipenv) to mitigate dependency confusion and substitution attacks.
* **Vulnerability Scanners**: Run `pip-audit` continuously within CI/CD pipelines to detect known CVEs in Python dependencies.
* **Private Package Indexes**: Maintain internal artifact repositories to vet and proxy external packages.
* **SBOM Generation**: Generate Software Bill of Materials using tools such as **Syft** and **CycloneDX**. Traditional SBOMs lack coverage for non-code assets such as model weights and training datasets, necessitating specialized ML artifact tracking.

## API Provider Assessment

* **Third-Party Risk**: Local infrastructure security controls do not mitigate risks introduced by external managed LLM service providers.
* **Due Diligence**: Evaluate vendor data governance, logging transparency, and security compliance postures.
* **Behavioral Monitoring**: Continuously monitor API model responses for output anomalies, data leakage, and prompt injection susceptibility.
* **System Prompt Governance**: Enforce strict internal version control over system prompts, isolating them from untrusted external repositories.
* **Sandboxed Evaluation**: Execute third-party model integrations within isolated, rate-limited sandboxed testing environments.
